# Обновление до единого MCPBox 1.3.0

[English upgrade guide](website/en/operations.md) | [Русская эксплуатационная инструкция](website/ru/operations.md)

MCPBox и MCPBoxPro объединены в одном Go-модуле `github.com/ArturSaleev/MCPBox`, одном frontend `html/src` и одном исполняемом файле `MCPBox`. Код бывших расширений находится в `internal/pro*`; префиксы сохранены для совместимости. Проверка коммерческой лицензии в приложение не включена. На весь объединённый проект распространяется существующая Apache-2.0 в LICENSE.

## Совместимость

- Админка требует входа: аккаунт, session token или bootstrap token. Это относится и к прежним общим `/api/projects`, `/api/servers` и другим административным маршрутам.
- Прежние `/api/pro/*`, scopes `pro:read`, `pro:write`, `pro:admin`, переменные `MCPBOX_PRO_*`, имена таблиц и token prefixes сохранены. Это технические имена, а не ограничение редакции.
- База по умолчанию `mcpbox.db`, `package_store` и другие относительные runtime-пути разрешаются рядом с исполняемым файлом. Сохраняется `.mcpboxpro/rag-shadow` для прежних RagBox bindings.
- Admin listener: `127.0.0.1:38181`; MCP listener: `0.0.0.0:38182`. Для прежнего MCPBox с портом 38180 задайте `MCPBOX_PORT=38180` явно.
- Интеграции RagBox и PolicyBox остаются отдельными сервисами. Их исходники и рабочие данные не перемещаются.

## Обновление существующей установки

1. Остановите старый сервис и сделайте резервную копию всей его рабочей директории, включая базу SQLite (и WAL/SHM, если есть), package_store, knowledge_base, `.mcpboxpro` и конфигурацию окружения.
2. Скачайте готовый бинарник из [релиза v1.3.0](https://github.com/ArturSaleev/MCPBox/releases/tag/v1.3.0) либо соберите MCPBox по README. Замените только исполняемый файл в прежней директории установки либо перенесите резервную копию данных в новую директорию рядом с бинарником. Не запускайте старый и новый сервис одновременно на одной базе.
3. Сохраните прежние переменные окружения, endpoints и секреты. При необходимости задайте прежние порты явно.
4. Для базы бывшего MCPBox используйте `./MCPBox admin create --email ... --password ...`, чтобы создать администратора. Для базы MCPBoxPro используйте существующий аккаунт.
5. Запустите MCPBox и проверьте проекты, MCP-подключения, пользователей и интеграции.

## Проверка данных и откат

Две разные рабочие базы автоматически не объединяются: перенос исходников не переносит пользовательские записи между установками. При запуске выполняются миграции схемы, поэтому сначала проверьте обновление на отдельной копии данных. Сохранение технических имён не гарантирует совместимость произвольной старой или изменённой вручную базы.

Проверьте вход администратора, проекты, серверы, авторизацию MCP, CLI-привязки и поиск по знаниям. При внешних PostgreSQL/RagBox и хранилищах журналов резервируйте их отдельно и проверяйте фактический runtime/shadow status. Выбор PostgreSQL не переносит автоматически все core-таблицы.

Для отката остановите новый процесс и восстановите предыдущий бинарник вместе с соответствующей копией данных до обновления и внешним состоянием. Замена только бинарника не отменяет миграций базы. Не удаляйте прежнюю установку и резервную копию до завершения проверки.

MCPBox собирается отдельно с `GOWORK=off`; соседний каталог MCPBoxPro не требуется. Исходники и рабочие данные отдельных RagBox/PolicyBox не перемещаются.

## Изменение default после опубликованного v1.3.0

В текущих исходниках MCP listener ограничен `127.0.0.1:38182`. При обновлении сетевой установки сохраните `MCPBOX_MCP_HOST=0.0.0.0` или `--mcp-host 0.0.0.0` явно, если нужен прямой вход с других машин. Локальный Qwen Studio и Tailscale Funnel на той же машине работают с loopback. Это изменение не меняет уже опубликованные бинарники v1.3.0. Подробности: [сеть и изоляция проектов](website/ru/network-access.md).
