# Единый MCPBox

MCPBox и MCPBoxPro объединены в одном Go-модуле `github.com/ArturSaleev/MCPBox`, одном frontend `html/src` и одном исполняемом файле `MCPBox`. Код бывших расширений находится в `internal/pro*`; префиксы сохранены для совместимости. Проверка коммерческой лицензии в приложение не включена. На весь объединённый проект распространяется существующая Apache-2.0 в LICENSE.

## Совместимость

- Админка требует входа: аккаунт, session token или bootstrap token. Это относится и к прежним общим `/api/projects`, `/api/servers` и другим административным маршрутам.
- Прежние `/api/pro/*`, scopes `pro:read`, `pro:write`, `pro:admin`, переменные `MCPBOX_PRO_*`, имена таблиц и token prefixes сохранены. Это технические имена, а не ограничение редакции.
- База по умолчанию `mcpbox.db`, `package_store` и другие относительные runtime-пути разрешаются рядом с исполняемым файлом. Сохраняется `.mcpboxpro/rag-shadow` для прежних RagBox bindings.
- Admin listener: `127.0.0.1:38181`; MCP listener: `0.0.0.0:38182`. Для прежнего MCPBox с портом 38180 задайте `MCPBOX_PORT=38180` явно.
- Интеграции RagBox и PolicyBox остаются отдельными сервисами. Их исходники и рабочие данные не перемещаются.

## Обновление существующей установки

1. Остановите старый сервис и сделайте резервную копию всей его рабочей директории, включая базу SQLite (и WAL/SHM, если есть), package_store, knowledge_base, `.mcpboxpro` и конфигурацию окружения.
2. Соберите MCPBox по README. Замените только исполняемый файл в прежней директории установки либо перенесите резервную копию данных в новую директорию рядом с бинарником. Не запускайте старый и новый сервис одновременно на одной базе.
3. Сохраните прежние переменные окружения, endpoints и секреты. При необходимости задайте прежние порты явно.
4. Для базы бывшего MCPBox используйте `./MCPBox admin create --email ... --password ...`, чтобы создать администратора. Для базы MCPBoxPro используйте существующий аккаунт.
5. Запустите MCPBox и проверьте проекты, MCP-подключения, пользователей и интеграции.

Две разные рабочие базы автоматически не объединяются: перенос исходников не переносит пользовательские записи между установками. Из общего `../go.work` убрана ссылка на MCPBoxPro, чтобы последующее удаление каталога не ломало Go workspace. Сам MCPBox также собирается отдельно с `GOWORK=off`. Папка MCPBoxPro и существующие runtime-данные этой операцией не удаляются. Публикация на GitHub выполняется отдельно.
