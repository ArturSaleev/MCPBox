# MCPBox v1.3.1 — Skills and simpler project access

[Русский](1.3.1.ru.md)

Release notes prepared for v1.3.1. The release has not been published yet.

MCPBox adds a Skills library: discover and import complete Skill packages, connect specific versions to projects, and make their instructions and resources available through MCP. Approved scripts can process uploaded files on the MCPBox server in a prepared Docker environment. This update also removes the PolicyBox integration and provides an explicit migration for affected projects.

## Skills library and project integration

- Browse the catalog with search and category filters. Start with the bundled catalog, refresh from a configurable HTTPS source, or import catalog JSON. A failed refresh preserves the last successful snapshot.
- Download packages from the catalog, import a public GitHub repository and Skill directory, or upload a ZIP. Preserve `SKILL.md`, scripts, references, assets, source information and license notices. Import does not execute package scripts or installation commands.
- Connect installed versions to one or more projects. New versions remain separate; catalog refreshes do not silently update installed packages or project bindings.
- Expose project Skills through MCP tools for discovery, reading instructions/resources, creating jobs, uploading inputs, running approved scripts and retrieving results. Projects containing only Skills can also accept MCP connections.
- Fix the optional-argument schema for `list_skills`: emit `required: []` instead of `null`, so strict clients can validate the tool catalog after OAuth.
- Advertise Skills tools and discovery guidance only for projects with connected Skills. Notify active project MCP SSE sessions when bindings change; clients with imported tool snapshots still need a catalog refresh.
- Build and refresh the central catalog with the included `skills-catalog` command and editable repository source list.

## Server execution and files

- Administrators configure Python, Node.js or Bash execution profiles, allowed scripts, timeouts, Docker images and optional network access. Environments are prepared explicitly before jobs run; jobs do not install dependencies.
- Run scripts in containers with an unprivileged user, a read-only root filesystem, resource limits and networking disabled by default. Host project directories, the Docker socket and MCPBox environment secrets are not passed into job containers.
- Upload inputs and download outputs through project jobs in the administration UI or MCP. Each job runs once and keeps its own files and logs.
- Prevent disconnecting a Skill while the project retains its jobs, including jobs that have not been run. Delete jobs explicitly after saving any needed files.
- Package/profile management requires administrator access. Existing project bearer/OAuth authentication, pause checks and project isolation also apply to Skills.

Docker must be installed and running on the MCPBox server for script execution. Browsing, importing and reading Skill instructions work without Docker. Third-party packages retain their own licenses; catalog inclusion and inspection do not guarantee safety or runtime compatibility.

See the [Skills guide](../SKILLS.md) for setup, limits, tools and API details. Chat clients must upload actual file bytes: a path on the user's computer is not a file on the MCPBox server. Clients decide when to discover and apply Skills; attaching a Skill does not guarantee automatic activation.

## Appearance

- Add Light, Dark and System modes with a persistent browser preference and a switch on both the sign-in screen and navigation.
- Use shared colors for pages, forms, dialogs, status labels, logs and notifications. Separate solid button colors from text accents for readable labels in both themes.

- Compact Knowledge Base cards keep upload and indexing actions visible. Usage help and collection details open through **!** buttons; search queries, results and errors share one dialog.

- Group Settings into System and Security with desktop navigation and a compact section selector on smaller screens. Collapse storage diagnostics, show PostgreSQL fields only when selected, and add contextual help. Load RagBox catalogs on demand and show connection failures inside RagBox with retry and technical details instead of unrelated startup error notifications.

- Reorder projects in the sidebar by dragging a handle, using up/down buttons or keyboard arrows. Save the preference per user in the current browser, preserve selection and status refreshes, and append new projects at the end.

## PolicyBox removal and access migration

- Remove the PolicyBox client, startup hooks, settings/API, runtime playground, remote audit fetch and binding CLI commands.
- Reject arbitrary user IDs as credentials. Preserve bearer/OAuth, project pause, MCP session isolation and server/tool permissions.
- Block legacy identity-verification projects until explicit administrator migration. Migration rotates the bearer credential, enables bearer authentication and pauses the project for access review; ordinary edits cannot clear the migration gate.
- Keep AgentBox direct bootstrap with project authentication. Retired PolicyBox runtime routes return `410 Gone`.
- Preserve inactive PolicyBox configuration, tables and external service data.

**Breaking change:** MCPBox no longer supplies PolicyBox identity/role/scope/context rules or manifests. Those rules are not automatically converted into project bearer authorization. Existing OAuth clients survive migration and must be reviewed before resuming the project. Read the [migration and rollback guide](../website/en/policybox-migration.md) before upgrading.

## Updating and backups

Back up the MCPBox database and runtime files before replacing the executable, including any configured operational database. Back up the database and `skill_store/` together to retain installed packages, profiles, project bindings and job files. Existing SkillBox data is not automatically migrated or deleted; import portable ZIP packages explicitly.

MCPBox remains open source under Apache-2.0. Skills do not require a separate paid edition.
