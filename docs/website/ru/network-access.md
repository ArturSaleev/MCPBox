# Сетевой доступ и изоляция проектов

[Оглавление](README.md) | [English](../en/network-access.md)

## Выбор способа подключения

| Сценарий | Настройка |
| --- | --- |
| Qwen Studio установлен на том же компьютере | Прямой URL `http://127.0.0.1:38182/mcp/<project-token>`; туннель не нужен |
| Облачный ChatGPT | Публикация MCP listener через `tailscale funnel 38182` или HTTPS reverse proxy; авторизация проекта включена |
| Прямой доступ из LAN / удалённый клиент | Явный bind на нужный интерфейс через `--mcp-host <адрес>`; настройка сети и при необходимости HTTPS/авторизации |

Текущие исходники по умолчанию используют loopback: админка `127.0.0.1:38181`, MCP `127.0.0.1:38182`. Опубликованные бинарники v1.3.0 выпущены до этого изменения и используют MCP `0.0.0.0:38182`; при их запуске явно сохраняйте `--mcp-host 127.0.0.1`. Существующей сетевой установке при обновлении с v1.3.0 нужно явно сохранить нужный адрес:

```bash
./MCPBox --mcp-host 0.0.0.0
```

Эквивалент в окружении — `MCPBOX_MCP_HOST=0.0.0.0`. Флаг имеет приоритет. Bind на все интерфейсы делает endpoint доступным там, где это допускают firewall и маршрутизация, но не добавляет авторизацию. Funnel на той же машине работает с loopback и такого bind не требует.

Сохраняйте разные адреса/порты админки и MCP. По умолчанию MCP listener обслуживает MCP/OAuth protocol routes и health, но не `/api/projects`, `/api/pro/*` и admin UI. Если намеренно настроить одинаковые адреса и порты обоих listener, они объединятся и административная поверхность также станет доступна на этом listener.

## Токены и границы изоляции

- Токен в URL выбирает проект и содержит 128 случайных бит. Если bearer-авторизация проекта выключена, знание URL открывает доступ к его включённым инструментам. Это секрет доступа, а не публичный идентификатор.
- При включённой bearer-авторизации одного URL недостаточно: каждый запрос должен содержать bearer проекта либо токен включённого OAuth-клиента того же проекта.
- Bearer и OAuth client tokens генерируются из 256 случайных бит. Сравнение bearer проекта выполняется за постоянное время. Случайность не заменяет rate limiting: исчерпывающая защита от перебора не заявляется. Для публичной установки задайте подходящие ограничения reverse proxy/сети.
- Списки и выполнение tools/resources/prompts разрешаются по включённым серверам запрошенного проекта. Чужой bearer/OAuth-токен и legacy SSE-сессия другого проекта отклоняются. Отключение OAuth-клиента, ротация bearer и пауза действуют на последующие запросы, но не отменяют уже выполненное действие инструмента.
- OAuth discovery, authorization и token endpoints доступны до входа — это нужно протоколу. Административный API от этого не становится публичным. Тесты OAuth проверяют PKCE/client validation и metadata защищённых проектов.
- Группировка проектов и CLI allowlist не являются sandbox ОС. Локальные программы работают с правами системной учётной записи MCPBox; целевые сервисы должны самостоятельно проверять доступ к данным. Проекты не дают файловой изоляции уровня ОС.

## Журналирование и проверки

Отказы bearer для известного проекта и несовпадения legacy-сессий записываются как `connect_blocked_bearer_auth` и `connect_blocked_session` со статическим описанием без переданных секретов. Неизвестный URL проекта получает 404. Другие журналы могут содержать метаданные запросов: ограничивайте доступ и не передавайте секреты в именах, промптах и аргументах.

Регрессионные тесты проверяют чужие bearer/OAuth-токены, списки и попытки вызова чужих tools/resources/prompts, сессии другого проекта, отзыв/ротацию токенов, паузу, аудит отказов и недоступность admin routes на MCP listener. Тесты listener проверяют локальный default и явное включение сети. Это локальная автоматическая проверка, а не пентест и не проверка реального внешнего ChatGPT/Funnel.
