# Базы знаний, логирование и интеграции

[Оглавление](README.md) | [English](../en/knowledge-integrations.md)

## Локальная RAG-база знаний

База знаний — поисковая коллекция документов. В локальном режиме MCPBox извлекает текст, делит его на пересекающиеся чанки и индексирует встроенным движком Bleve. При запросе наиболее подходящие чанки могут передаваться AI-процессу как контекст.

RAG помогает получать ответы, опирающиеся на документы организации, но не гарантирует правильность. Поддерживайте источники в актуальном состоянии, проверяйте типовые запросы и сохраняйте первоисточник данных.

### Создание локальной базы

1. Откройте **Knowledge → Create knowledge base**.
2. Укажите название.
3. Выберите **Local / Bleve only** (`bleve_only`).
4. При необходимости укажите source folder, доступный сервисному пользователю MCPBox на чтение.
5. Сохраните базу, загрузите файлы или проиндексируйте папку, затем привяжите базу к нужному проекту.

Для загружаемых файлов MCPBox создаёт managed folder. Режим **Keep** сохраняет оригинал для будущих переиндексаций, а **Transient** удаляет оригинал после успешной обработки. Архивы `.zip`, `.tar`, `.tgz` и `.tar.gz` распаковываются и обрабатываются пакетно.

### Карточки коллекций и поиск

На странице «База знаний» загрузка файлов и индексация папки доступны в компактных карточках. Кнопка **!** в заголовке открывает справку, а **!** в карточке — пути, параметры сервисов и статус RagBox выбранной коллекции. Кнопка **Поиск** открывает окно с запросом и результатами, включая состояния загрузки, отсутствия совпадений и ошибки.

### Форматы и ограничения

Локальный extractor поддерживает `.txt`, `.md`, `.csv`, `.docx`, `.xlsx`, `.pptx`, `.pdf`, `.go`, `.js` и `.php`. Индексируется извлекаемый текст, а не визуальная вёрстка; сканированные PDF без текстового слоя могут не дать полезного результата.

Контент делится на чанки до 2 000 символов с overlap. Поиск возвращает ограниченное число релевантных чанков (по умолчанию 10). Это лёгкая локальная база знаний, а не замена распределённой vector database. Ёмкость определяется диском, RAM, размером документов и нагрузкой; большие или не связанные по смыслу массивы лучше разделять на коллекции.

Автоматическая переиндексация каждые 10 минут работает только в `bleve_only`. Не указывайте папки с большими зависимостями или сборочными артефактами: `node_modules`, `vendor`, `.git`, `dist` и `build` пропускаются, но лучше использовать небольшую отобранную папку-источник.

## Подключение RagBox

RagBox нужен, когда требуется отдельный сервис ingestion/retrieval, workspaces или внешняя vector database. Настройте его в **Settings → RagBox**: base URL, tenant ID, least-privilege **service token** для workspace/ingestion/search, отдельный **admin token** только для админ-действий, timeout, write mode и search mode.

MCPBox проверяет соединение при сохранении. Для базы с RagBox выберите `ragbox_only` или `dual`, затем существующий RagBox workspace либо vector connection для managed workspace. В UI доступны SQLite, Qdrant, pgvector, Milvus, Weaviate, OpenSearch, Elasticsearch, Pinecone и Chroma.

`dual` поддерживает Bleve и RagBox синхронно, `ragbox_only` использует только RagBox. В этих двух режимах авто-переиндексация Bleve отключена во избежание дублирующей фоновой нагрузки; используйте upload, sync source или ручную синхронизацию.

### Навигация настроек и ошибки подключения

В настройках разделы **Хранилище** и **RagBox** объединены в группу «Система», а **Доступ**, **Пользователи** и **Сессии** — в «Безопасность». На небольшом экране раздел выбирается из списка. Кнопка **!** открывает общую справку; bootstrap и статистика синхронизации раскрываются в хранилище. Поля PostgreSQL появляются при выборе этого backend.

Векторные подключения и workspaces RagBox загружаются, когда они нужны в разделе RagBox или редакторе базы знаний. Сохранённый адрес/token означает наличие настроек, а не доступность сервиса. При ошибке раздел показывает сообщение с кнопкой **Повторить** и раскрываемыми техническими подробностями. Проверьте запуск сервиса, доступность сохранённого URL с сервера MCPBox и действительность admin token. `127.0.0.1` означает машину или контейнер, где работает MCPBox. Локальному поиску Bleve RagBox не требуется.

## Логирование и аналитика

В **Logs** доступен audit trail, в **Analytics** — количество запросов, ошибки, latency, трафик и недавние failures. Логи фильтруются по проекту и Access/Policy-активности, обновляются и экспортируются из текущей видимой выборки.

Используйте их для диагностики MCP-вызовов, health checks, операций с базой знаний, изменений конфигурации и доступа. Не записывайте secrets и персональные данные в названия проектов, промпты, headers или request metadata: они могут сохраниться в operational logs.

## Остальные настройки

### Переход с PolicyBox

Интеграция удалена из текущих исходников. Для старых проектов предусмотрена явная [миграция с сохранением данных](policybox-migration.md).

### Storage

В **Settings → Storage** bootstrap/system слой MCPBox остаётся на SQLite, а PostgreSQL может использоваться как operational backend. Для логов можно оставить operational storage либо выбрать ClickHouse или Elasticsearch. Меняйте эти настройки только с backup и проверенным rollback plan; после сохранения проверьте runtime и shadow status.

### Администрирование доступа

В интерфейс администрированияе управляются пользователи, роли, сессии и API tokens. Выдавайте минимально необходимые роли, отзывайте неактивные сессии/tokens и используйте OIDC SSO, если этого требует организация.
