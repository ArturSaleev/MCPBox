# Безопасный запуск MCPBox в production

Эта страница для человека, который запускает сервер. Не нужно быть экспертом по MCP — просто выполните пункты по порядку.

## Простая production-схема

Разместите MCPBox на сервере внутри сети компании. Admin-интерфейс оставьте приватным, а наружу через HTTPS публикуйте только MCP endpoint проекта, если он нужен внешним клиентам.

```text
Администраторы → private admin UI → MCPBox
AI-клиенты      → HTTPS reverse proxy → MCP endpoint проекта
```

## Перед запуском

1. Создайте отдельного пользователя ОС для MCPBox. Не запускайте сервис от root или Administrator.
3. Создайте первого Pro-администратора и войдите в интерфейс.
4. Оставьте admin UI только для администраторов: `127.0.0.1`, VPN или SSH tunnel.
5. Перед публичным MCP endpoint поставьте reverse proxy, например Nginx или Caddy, и настройте корректный HTTPS certificate.
6. Откройте в firewall только нужные порты. Обычно это `443` reverse proxy; raw admin port `38181` наружу не публикуется.
7. Для каждого проекта, доступного вне доверенной сети, включите bearer authentication.
8. Проверьте один MCP-вызов и **Logs** до приглашения пользователей.

MCPBox проверяет admin session/token не только на `/api/pro/*`, но и на общих административных маршрутах проектов, серверов, логов и OAuth-подключений. Полный OAuth client token доступен только principal с `pro:admin`. Не публикуйте admin-порт как часть публичного MCP endpoint.

## Идея reverse proxy

Используйте публичное HTTPS-имя, например `https://mcp.example.com`. Proxy передаёт запросы на внутренний MCP port MCPBox. Точный конфиг зависит от сети и провайдера сертификатов, поэтому храните его в репозитории инфраструктуры.

Главное правило: HTTPS снаружи, внутренний HTTP только в защищённой сети при необходимости и никакого публичного доступа к admin port.

## Важные правила безопасности

- У каждого администратора должна быть собственная учётная запись.
- Используйте SSO, если организации нужен централизованный доступ.
- По возможности храните passwords и tokens в secret manager.
- Выдавайте минимально необходимые права пользователям, service accounts и MCP-серверам.
- Проверяйте каждый пакет Marketplace и tool перед включением.
- Создавайте отдельный проект для каждой независимой бизнес-области или границы доступа к данным.
- Регулярно обновляйте сервер, пакеты и ОС.
- Просматривайте audit logs и отзывайте неиспользуемые sessions/tokens.

## Backup и восстановление

Перед обновлением или изменением конфигурации сохраните защищённую копию:

- базы MCPBox — обычно `mcpbox.db` в рабочей директории;
- managed folders и локальных indexes баз знаний;
- конфигурации reverse proxy и service; и

Не кладите backup в публичный репозиторий. Проверьте восстановление на тестовом сервере: остановите MCPBox, восстановите базу и данные базы знаний вместе, затем запустите сервис и проверьте проект, сервер и поиск по базе знаний.

## Обновление

1. Сделайте backup.
2. Остановите MCPBox.
3. Замените executable на одобренный релиз.
4. Запустите сервис.
5. Проверьте вход администратора, один MCP project и логи.

Если что-то не работает, остановите новую версию, верните предыдущий executable и соответствующую копию базы, затем разберите ошибку в тестовой среде.
