# Резервное копирование, обновление и восстановление

[Оглавление](README.md) | [English](../en/operations.md)

## Постоянная установка

Храните собранный `MCPBox` в отдельном доступном для записи каталоге. Запускайте от выделенной системной учётной записи. Переменные окружения, перезапуск и сбор журналов настройте в менеджере служб. Универсального установщика systemd, launchd, службы Windows или Docker Compose в репозитории нет.

В текущих исходниках оба listener по умолчанию слушают localhost. В опубликованных бинарниках v1.3.0 MCP ещё слушает все IPv4-интерфейсы, если не настроен явно. Для удалённого администрирования можно использовать SSH-туннель:

```bash
ssh -N -L 38181:127.0.0.1:38181 user@server
```

Откройте `http://127.0.0.1:38181/` локально. Внешний MCP публикуйте через HTTPS reverse proxy с настроенной авторизацией проекта. См. [безопасность production](production-security.md).

## Согласованная резервная копия

1. Зафиксируйте версию бинарника, настройки сети, интеграции и расположение внешних хранилищ.
2. Остановите MCPBox менеджером служб и убедитесь, что процесс завершился. Перед копированием SQLite остановите запись.
3. Скопируйте весь каталог установки/данных в защищённое хранилище, включая скрытые папки: `mcpbox.db`, оставшиеся `mcpbox.db-wal` и `mcpbox.db-shm`, `package_store/`, `knowledge_base/`, `.mcpboxpro/`.
4. Отдельно сохраните исходные папки документов за пределами установки, окружение службы, секреты и конфигурацию reverse proxy.
5. Для PostgreSQL, внешнего хранилища журналов и RagBox сделайте согласованные копии средствами соответствующих сервисов. Копия SQLite не сохраняет данные этих систем.
6. Запустите MCPBox и проверьте вход, проекты, серверы и поиск по знаниям. Защищайте копии и периодически проверяйте восстановление.

## Обновление и миграция

Остановите старый сервис, сделайте описанную выше копию и замените только исполняемый файл в существующей установке. Сохраните данные и окружение. Не запускайте две версии на одной SQLite-базе. При старте выполняются аддитивные миграции схемы; для отката сохраняйте прежний бинарник вместе с копией данных до обновления.

Возможности бывшего MCPBoxPro входят в MCPBox без активации. Аккаунты и совместимые технические имена сохраняются. Если в старой установке ещё нет пользователей, создайте администратора по [инструкции установки](installation.md). Для сохранения прежнего порта `38180` задайте `MCPBOX_PORT=38180`. Две независимые базы автоматически не объединяются.

## Восстановление и откат

Остановите сервис. Сначала восстановите соответствующие друг другу бинарник, полный снимок данных, внешние хранилища и конфигурацию в отдельной тестовой установке. Ограничьте её сетевую доступность и исключите непреднамеренные обращения к production-интеграциям. Проверьте владельца файлов и права. На один каталог данных запускайте один процесс.

Проверьте вход, число и настройки проектов, один локальный сервер, один удалённый при наличии, вызов MCP-инструмента клиентом и типовой поиск по знаниям. Проверьте runtime/shadow status хранилищ и ошибки. Возможность пересоздать индекс не заменяет оригиналы: после transient-загрузки исходный файл может уже отсутствовать.

Для отката неудачного обновления остановите новый процесс и восстановите прежний бинарник вместе с согласованной копией данных и внешнего состояния до обновления. Замена одного исполняемого файла не откатывает изменения базы.

## Диагностика перед изменением данных

`GET /healthz` подтверждает доступность HTTP-сервиса, но не всех интеграций. Используйте Logs/Analytics и проверки отдельных серверов. При `401` проверьте тип и значение токена, при `403` — scope и авторизацию проекта. Пауза проекта, отключённый сервер, отсутствующий бинарник или недоступная зависимость требуют отдельных исправлений. См. [диагностику](troubleshooting.md).

Настройки по умолчанию выше относятся к текущим исходникам. Опубликованный v1.3.0 использует прежний MCP bind `0.0.0.0`; до обновления явно задавайте `--mcp-host 127.0.0.1`. Удалённый доступ включается через `--mcp-host 0.0.0.0` или `MCPBOX_MCP_HOST=0.0.0.0`. [Сеть и изоляция проектов](network-access.md).
