# Проверка скачанного релиза

[Оглавление](README.md) | [English](../en/release-verification.md)

Скачивайте бинарники из [официального релиза GitHub](https://github.com/ArturSaleev/MCPBox/releases/tag/v1.3.0). Перед переименованием и запуском вычислите SHA-256 файла и сравните со строкой именно его имени в [v1.3.0 SHA256SUMS](../../checksums/v1.3.0-SHA256SUMS.txt).

## Проверка одного файла

macOS, например Apple Silicon:

```bash
shasum -a 256 MCPBox-macos-arm64
```

Linux, например Intel/AMD:

```bash
sha256sum MCPBox-linux-amd64
```

Windows PowerShell, например Intel/AMD:

```powershell
Get-FileHash .\MCPBox-windows-amd64.exe -Algorithm SHA256
```

Сравните все 64 шестнадцатеричных символа; регистр букв не важен. При несовпадении не запускайте файл: проверьте версию и архитектуру, повторите скачивание из официального релиза и разберитесь с повторной ошибкой. Совпадение хеша подтверждает идентичность файла, но не заменяет цифровую подпись, нотариализацию или проверку уязвимостей.

Если скачаны все шесть бинарников и файл сумм, на Linux используйте `sha256sum -c v1.3.0-SHA256SUMS.txt`, на macOS — `shasum -a 256 -c v1.3.0-SHA256SUMS.txt`. При скачивании одного бинарника эти команды сообщат об отсутствии остальных; в таком случае используйте проверку отдельного файла выше.

## Источник сумм и состояние проверки

Манифест v1.3.0 содержит значения `sha256:` из GitHub API для файлов релиза. Все шесть локальных релизных файлов независимо проверены: хеши совпали с GitHub. Это суммы уже опубликованных файлов v1.3.0; новая сборка текущих исходников может иметь другие значения. Манифест добавлен в репозиторий; его загрузка отдельным asset релиза ожидает доступа на запись.

| Опубликованный файл | SHA-256 совпал с GitHub | Проверка запуска |
| --- | --- | --- |
| macOS arm64 | Да | Отдельный каталог данных на текущем Apple Silicon Mac; не чистая ОС |
| macOS amd64 | Да | Ожидает проверки на Intel macOS |
| Linux amd64 | Да | Ожидает проверки на чистой Linux amd64 |
| Linux arm64 | Да | Ожидает проверки на чистой Linux arm64 |
| Windows amd64 | Да | Ожидает проверки на чистой Windows amd64 |
| Windows arm64 | Да | Ожидает проверки на чистой Windows arm64 |

Smoke-проверка macOS arm64 охватывает создание администратора, вход, health, встроенный UI, защищённый API, создание/список проектов и сохранение данных рядом с бинарником при запуске из другого каталога. Она не подтверждает совместимость со всеми версиями ОС и внешними MCP/SSO-сервисами.

## Предупреждения безопасности и ошибки запуска

- **macOS Gatekeeper:** возможно предупреждение о неизвестном разработчике или отсутствии нотариализации. Проверьте источник и хеш, изучите [инструкцию Apple](https://support.apple.com/102445). При сообщении о вредоносном коде или повреждении остановитесь. Не отключайте Gatekeeper и не снимайте quarantine-атрибуты как шаг установки.
- **Windows SmartScreen:** возможно предупреждение о репутации незнакомого файла. Проверьте источник и хеш, соблюдайте политику организации. Оставьте SmartScreen/Defender включёнными. См. [рекомендации Microsoft](https://support.microsoft.com/en-us/office/protect-my-pc-from-viruses).
- **Неверная архитектура / формат:** выберите amd64 для Intel/AMD или arm64 для ARM. Наличие эмуляции/трансляции не предполагается.
- **Permission denied:** на macOS/Linux выдайте проверенному файлу право запуска командой `chmod +x MCPBox`. Каталог установки должен быть доступен для записи вашей учётной записи.
- **Порт занят:** выберите свободные admin/MCP-порты и согласуйте их с URL клиента и конфигурацией туннеля.

## Проверки перед публикацией

Основной отслеживаемый скрипт — `./build-release.sh all`. Он создаёт шесть плоских бинарников с именами как у публичных assets и `release/SHA256SUMS`. Режим `host` создаёт только бинарник текущей платформы и манифест этой сборки. Существующие целевые бинарники заменяются только после успешной сборки всех запрошенных целей; остальные файлы и runtime-данные сохраняются. Старые игнорируемые `release/build-release.*` не являются поддерживаемой точкой входа.

Для сборки нужны Go, установленные frontend npm-зависимости и `sha256sum` либо `shasum`. Публикуйте манифест вместе с бинарниками одной сборки. До релиза проверьте каждый файл на родной чистой ОС: первый администратор, вход, UI, проект, один MCP-вызов, сохранение данных, перезапуск и обновление копии базы 1.2.x с резервной копией. Запишите ОС/версию и результат. Кросс-сборка и совпадение хешей не заменяют проверку запуска.
