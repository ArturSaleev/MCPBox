# Политика безопасности

[English](SECURITY.md)

## Поддерживаемые версии

Исправления безопасности ориентированы на последний стабильный релиз MCPBox (сейчас v1.3.0) и текущую ветку разработки. Версии 1.2.x и прежний отдельный MCPBoxPro не являются самостоятельными ветками security-поддержки; обновляйтесь по [инструкции миграции](docs/MERGE.md). Сообщение о старой версии полезно, если проблема также затрагивает текущий код.

Поддержка выполняется по мере возможностей. Политика не обещает срок ответа, backport для каждой версии, bug bounty или независимый аудит.

## Приватный отчёт через GitHub

Не публикуйте предполагаемые уязвимости, рабочие exploits, токены и данные пользователей в публичных Issues, PR и обсуждениях.

В [репозитории MCPBox](https://github.com/ArturSaleev/MCPBox/security/advisories) используйте **Security → Advisories → Report a vulnerability**. Отчёты GitHub Private Vulnerability Reporting доступны автору и уполномоченным сопровождающим/участникам расследования.

**Состояние настройки:** при подготовке политики приватные отчёты были выключены. Добавление `SECURITY.md` не включает эту функцию GitHub. До её включения владельцем кнопка отчёта может отсутствовать. В таком случае создайте только публичный административный запрос **Enable private vulnerability reporting**, без деталей уязвимости, затронутых систем, proof of concept и секретов. Дождитесь приватного канала, прежде чем передавать подробности. Email для security reports проект не использует.

См. [инструкцию GitHub по приватным отчётам](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/report-privately).

## Что приложить к приватному отчёту

Укажите затронутый релиз/commit, ОС и архитектуру, относящиеся к проблеме настройки без секретов, последствия, необходимые условия, минимальные шаги воспроизведения и возможное исправление. Используйте синтетические примеры. Не отправляйте рабочие базы, действующие токены и посторонние персональные данные. Согласуйте раскрытие с сопровождающим и дайте время на исследование до публикации деталей эксплуатации.

Проверяйте только собственные системы или системы, на тестирование которых получено разрешение. Не обращайтесь к чужим данным, не нарушайте работу сервисов и не сканируйте массово чужие установки.

## Границы развёртывания

URL проектов и токены — секреты. Проекты и CLI allowlist не являются sandbox ОС. Выдавайте минимальные права системным/служебным аккаунтам, включайте авторизацию внешних проектов, сохраняйте админку приватной и защищайте копии/журналы. См. [сеть и изоляцию](docs/website/ru/network-access.md) и [production-настройки](docs/website/ru/production-security.md).

В текущих исходниках MCP по умолчанию локален; опубликованный v1.3.0 сохраняет прежний bind на все интерфейсы без явной настройки. Изменение документации не меняет уже скачанный бинарник.
