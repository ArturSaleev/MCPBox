# MCPBox

**MCP-серверы, CLI-команды, базы знаний и Skills — один MCP URL для каждого проекта.**

Управляйте инструментами AI из одной панели: объединяйте их по проектам, настраивайте доступ и проверяйте состояние серверов и историю вызовов. MCPBox — бесплатное приложение с открытым исходным кодом под Apache-2.0, со встроенным веб-интерфейсом и локальным хранением данных.

[Скачать v1.4.0](https://github.com/ArturSaleev/MCPBox/releases/tag/v1.4.0) · [Документация](docs/website/ru/README.md) · [Сайт](https://mcpbox.sh) · [Обсуждения](https://github.com/ArturSaleev/MCPBox/discussions) · [English](README.md)

## Зачем MCPBox

- **Проекты вместо разрозненных конфигов.** Объединяйте локальные `stdio` и удалённые `http_stream` MCP-серверы и подключайте клиент к одному адресу проекта.
- **Контролируемый доступ.** Пользователи, роли, сессии, API-токены, авторизация MCP-подключений и опциональный OIDC SSO.
- **CLI для AI.** Открывайте проекту только разрешённые операции локальных программ и точные наборы аргументов.
- **Skills для проектов.** Ищите навыки в каталоге, импортируйте пакеты GitHub/ZIP и подключайте конкретные версии с инструкциями и ресурсами через MCP.
- **Скрипты на сервере.** Загружайте файлы в задания и запускайте разрешённые Python, Node.js и Bash-скрипты в подготовленном администратором Docker-окружении.
- **Знания рядом с инструментами.** Индексируйте документы локально через Bleve или подключайте отдельный RagBox.
- **Понятное состояние.** Проверки здоровья, просмотр tools/resources/prompts, журналы вызовов и базовые метрики.
- **Одна установка.** Go-бинарник со встроенным React UI; для готового релиза Go и Node.js не нужны. Зависимости подключаемых инструментов устанавливаются отдельно.

## Как это работает

Например, создайте проект для работы с кодом: подключите MCP-сервер для файлов, второй сервер для вашей системы задач, разрешите Git `status` и `diff`, добавьте коллекцию документации. Клиент получает единый URL проекта, а MCPBox направляет вызовы нужным инструментам.

```text
AI-клиент → MCP URL проекта → MCP-серверы + разрешённые CLI + база знаний + Skills
```

MCP-серверы и CLI-команды выполняются с правами сервисов и системной учётной записи. Промпт проекта не заменяет авторизацию в целевой системе.

## Skills: инструкции и работа с файлами

1. Откройте **Skills**, найдите пакет в каталоге или импортируйте его из публичного GitHub-репозитория либо ZIP. Скачивание пакета не запускает его скрипты.
2. Подключите установленную версию во вкладке **Skills** проекта. Клиент получает инструкции через `list_skills`, `get_skill` и `read_skill_file`; инструменты Skills доступны только проектам с подключёнными навыками. После изменения подключений клиенту с кэшем инструментов может понадобиться обновление соединения.
3. Для выполнения скриптов администратор выбирает среду, точные разрешённые скрипты и подготавливает Docker-образ. Создайте задание, загрузите входные файлы, запустите разрешённый скрипт и скачайте результат. Путь к файлу на компьютере клиента не передаёт сам файл на сервер.

Docker нужен на сервере **только для выполнения скриптов**; каталог, импорт и чтение инструкций работают без него. Задания выполняются непривилегированным пользователем, с корневой файловой системой только для чтения, ограничениями ресурсов и без сети по умолчанию. Подготовка зависимостей — отдельное действие администратора, которое может выполнять код сборки и обращаться к сети. Эти ограничения не гарантируют безопасность стороннего кода: проверяйте пакет и его лицензию перед разрешением запуска.

[Каталог, настройка выполнения и MCP-инструменты Skills](docs/SKILLS-ru.md).

## Быстрый старт с бинарником

1. Скачайте файл выше и поместите в отдельную доступную для записи папку. На macOS/Linux переименуйте в `MCPBox`; на Windows — в `MCPBox.exe`.
2. Откройте терминал в этой папке и запустите:

   **macOS / Linux**

   ```bash
   chmod +x MCPBox
   ./MCPBox --mcp-host 127.0.0.1
   ```

   **Windows PowerShell**

   ```powershell
   .\MCPBox.exe --mcp-host 127.0.0.1
   ```

3. В интерактивном терминале следуйте подсказкам для создания первого администратора. Откройте [http://127.0.0.1:38181/](http://127.0.0.1:38181/) и войдите.
4. Создайте проект, добавьте MCP-сервер и проверьте его состояние. Для CLI подключите запись реестра к проекту; для базы знаний — коллекцию; для Skills — установленную версию навыка.
5. Скопируйте URL `http://127.0.0.1:38182/mcp/<project-token>` из UI и настройте в клиенте MCP HTTP-подключение с авторизацией проекта.

Флаг в примере ограничивает MCP локальной машиной, в том числе для опубликованных бинарников v1.3.0, где прежний default — `0.0.0.0:38182`. В текущих исходниках MCP уже слушает `127.0.0.1:38182` по умолчанию; админка — `127.0.0.1:38181`. Для удалённого подключения настройте HTTPS и доступ по [инструкции безопасности](docs/website/ru/production-security.md).

## Подключение AI-клиентов

**Проверенный владельцем проекта сценарий:** локально установленное приложение **Qwen Studio** подключается к MCPBox на той же машине по `http://127.0.0.1:38182/mcp/<project-token>`, с настроенной авторизацией проекта. Tailscale для этого не нужен. Работа веб-версии Qwen Studio не подтверждена. Для облачного ChatGPT нужен публичный HTTPS endpoint; Tailscale Funnel — один из вариантов его получения.

Используйте клиент с поддержкой MCP HTTP и нужного способа авторизации. Установка соединения и успешный вызов инструмента проверяются отдельно для конкретной версии клиента; универсальная совместимость со всеми AI-клиентами не заявляется.

- [ChatGPT: настройка подключения и OAuth](docs/website/ru/chatgpt.md).
- [Проекты, серверы и авторизация](docs/website/ru/projects-marketplace-prompts.md).
- В коде есть launcher для Ollama/llama.cpp и deeplink LM Studio; это вспомогательные способы настройки, а не подтверждение проверки каждой версии этих приложений. [Требования](docs/website/ru/configuration.md).

## Обновление прежних установок

Возможности бывшего MCPBoxPro включены в единый открытый MCPBox; лицензия и активация не требуются. Технические имена `/api/pro/*`, `pro:*` и `MCPBOX_PRO_*` сохранены для совместимости. Перед заменой бинарника прочитайте [миграцию](docs/MERGE.md) и [резервное копирование](docs/website/ru/operations.md).

**В v1.4.0 удалена интеграция PolicyBox.** Старым проектам с проверкой идентификации нужна явная миграция администратора с заменой bearer credential и постановкой на паузу для проверки доступа. Данные PolicyBox сохраняются. См. [переход с PolicyBox](docs/website/ru/policybox-migration.md).

## Сборка из исходников

Нужны Go 1.26.9+ и Node.js/npm. Выполните из корня репозитория:

```bash
npm --prefix html ci
npm --prefix html run build
GOWORK=off go build -o MCPBox .
./MCPBox
```

При первом запуске в интерактивном терминале создайте администратора по подсказкам, затем войдите в [админку](http://127.0.0.1:38181/). Для запуска службы без терминала заранее создайте аккаунт:

```bash
./MCPBox admin create --email admin@example.com --password 'replace-with-a-unique-password' --name 'Admin'
```

Пароль — минимум 8 символов. Команда обновляет существующий локальный аккаунт с тем же email; пароль в аргументе может попасть в историю shell и список процессов. Для первого запуска с терминалом предпочтителен интерактивный ввод. В PowerShell используйте `.\MCPBox.exe` вместо `./MCPBox`.

1. Создайте проект в админке.
2. Добавьте MCP-сервер, разрешённую CLI-команду, базу знаний или Skill.
3. Проверьте состояние и скопируйте MCP URL проекта из UI.
4. Подключите MCP-клиент с нужным для проекта способом авторизации.

| Интерфейс | По умолчанию |
| --- | --- |
| Admin UI / API | `http://127.0.0.1:38181/` |
| MCP проекта | `http://<server>:38182/mcp/<project-token>` |

Текущие исходники по умолчанию ограничивают MCP адресом `127.0.0.1`. Опубликованные бинарники v1.3.0 используют `0.0.0.0`; для них явно задайте `MCPBOX_MCP_HOST=127.0.0.1`. Порты и адреса меняются через `MCPBOX_HOST`, `MCPBOX_PORT`, `MCPBOX_MCP_HOST`, `MCPBOX_MCP_PORT`. Admin-токены и bearer проекта имеют разные назначения.

## Данные и обновление

Данные по умолчанию находятся рядом с бинарником: `mcpbox.db`, `package_store/`, `knowledge_base/`, `skill_store/`, `.mcpboxpro/`. Базу и `skill_store/` сохраняйте вместе: они содержат связанные метаданные, пакеты, профили и файлы заданий Skills. Используйте постоянный каталог с правами записи; `go run` создаёт временный бинарник. Перед заменой установленной версии остановите процесс и сохраните согласованную копию данных. Две базы автоматически не объединяются.
